# Plan of v0.2.0

Working plan; the team decides what Phase A lists and may change any part. It turns `docs/design/vision.md` into work that several agents of two people can do in
parallel without colliding, and that is playable at every step. There are no time slots: the order and the priority
tiers decide what comes first, and everything is frozen at 07:00 on Sunday 2026-11-15.

## How the work is shaped
- **One branch, `v0.2.0`, one pull request at the end.** Every step is a commit that leaves the game running, numbered
  0.1.1, 0.1.2, ... (`AGENTS.md`).
- **A skeleton first, then parallel packages.** Today the whole game lives in `scripts/main.gd` (1,609 lines, every
  screen a function in one file), so any two agents would edit the same file. One agent splits it first; after that,
  each package owns its own files.
- **A vertical slice before breadth.** The first goal is one mission played end to end through every station, on the
  web, with two people online. Only then more missions, more parts, more mini-games.
- **Playable at every step.** CI stays green; after each package lands, someone plays the full journey on the web
  build and looks at it.

## Phase A: decisions (the team)
1. The game's name (it also names the Firebase project and the web address).
2. The visual direction, chosen from two or three written directions; shown visually only if the team asks for it.
3. The stations and how players share them (proposal below), and the mission list for v0.2.0 (from
   `kb/research/missions.md`).
4. Who owns which package (proposal below), and which accounts and machines build tonight.

## Phase B: the skeleton (one agent, in order, before anything else)
- **0.1.1 Screens apart.** `main.gd` becomes a small flow controller; each screen moves to its own script under
  `scripts/screens/` (menu, team, missions, builder, route, review, launch, flight, operations, ground control,
  report); shared UI helpers to `scripts/ui/`; one `GameState` autoload holds the mission, the team and the phase.
  Behavior unchanged: the walkthrough screenshots and the fuzz test match v0.1.0.
- **0.1.2 Data apart, in English.** The catalogs in `game_data.gd` move to `data/*.json` (missions, parts, launchers,
  orbits, events, objectives, texts), each value with its source, loaded by `GameData`. The interface text is English.
  The schema is documented in `docs/architecture.md`, so content agents never touch code.
- **0.1.3 The room.** One `Room` interface for shared state (create, join with a code, take a station, propose and
  sign off, receive every change), with two implementations behind it: the same screen (no network) and Firebase
  Realtime Database through the page's JavaScript (the bridge measured in `kb/tech/platform-options.md` section 6).
  The web build deploys to a Firebase Hosting preview on every push.

## Phase D: together
The full journey played on the web, solo and with two to four browsers; an agent that built none of it reviews it;
a person with no context plays the first mission and says what it is about; findings fixed at their cause.

## Phase E: delivery
The pull request `v0.2.0: ...` when complete and green; a team member merges; the release deploys to Firebase Hosting;
someone plays the live game. In parallel from Phase D: the 7-slide deck in English, the 30-second video, the project
page text, the references and the AI disclosure (`docs/team/pitch-outline.md`, `kb/challenge/event-and-judging.md`).

## Priority tiers (what is cut first if time runs short)
1. **Must:** the skeleton; English; the web build on Firebase; online rooms for up to four plus the same screen; the
   builder, the route, launch and landing flown by the pilot, ground control with the signal and at least two failure
   mini-games; three missions end to end (one Earth orbit, one landing, one that never returns); the celebration
   report with bonuses and the twin mission; modeled craft and a UI of its own; sound effects; credits.
2. **Should:** six or more missions, a sample-return mission, more mini-games, the online leaderboard and gallery,
   the characters' humor, music.
3. **Could:** a sandbox, saved and shared designs, dialogue.

## Stations (proposal)
Mission director (money, time, launcher, the team's calls), engineer (the builder), scientist (instruments, targets,
extra objectives), pilot (launch, burns, landing), ground control (signal, data, failures). With fewer than five
players, stations combine; alone, one player takes every station with help.

## Ownership (proposal)
- **The teammate:** C7 look and sound (he researched the Blender pipeline) and C1 builder (he wrote the craft builder).
- **The lead's agents:** the skeleton, then C2, C3, C4, C5, C6, C8, C9.
- Shared contracts (data schemas, `GameState`, `Room`, `AGENTS.md`) change only by agreement of both.
